Turn 1 · Node library — discoverability, consistency, comprehension

Six options, split by how much they cost to ship

The three feedback items aren't three problems — they're one. The library is organised around where a thing lives rather than what a user is trying to do, so every unknown becomes a navigation task, and everything the taxonomy can't answer got patched with a link out to docs.

P1 · FIND
Category-first hierarchy
To find a thing you must already know which of six buckets holds it. Is a Text Classifier an Agent or a Flow node? It's both, filed once.
P2 · CONSISTENCY
Four help affordances, three row shapes
Header ?, row ⓘ, hover tooltip and a "What can I build with…" link all coexist. Users learn each pane separately.
P3 · UNDERSTAND
Descriptions define, never advise
Descriptions say what a thing is ("LLM powered agent"), never when to reach for it or what it costs. The real answer lives in a doc site, one tab away.
P4 · COST OF A PICK
A one-slot pane with no memory
The pane holds one view at a time and forgets. Building a five-node agent = five in-and-out trips, each losing scroll, search and filter state.

Short term

Same data, same components. Re-arranging what already exists.
1a

Flatten it — one list, filters not folders

Kill the six drill-in panes. One scrolling list, categories become filter chips, search is always on screen. Nothing is ever "inside" anything, so there is no back button and nothing to lose.

SolvesP1, P4. One row pattern everywhere also lands most of P2. CostLow — a re-layout of existing lists. Risk248 items in one list needs good ranking; "most used in your org" carries it until semantic search lands.
1b

One help affordance: the peek panel

Delete the ?, the ⓘ, the tooltip and the inline doc link. One rule: select a block, see everything about it — in a panel beside the list, not a tab away. Docs get pulled in rather than linked out.

Medium term

1d

Describe the job, get a shortlist

Semantic search stops being a search box and becomes the front door. Results ignore the taxonomy entirely and each one says why it matched — which is the comprehension fix hiding inside the discoverability fix.

1e

Ship recipes, not just parts

No amount of per-node documentation teaches how nodes work together — that's the actual gap behind "I don't understand how to use these." A recipe is a pre-wired assembly you drop, then edit.

1f

Make the docs a field, not a link

The "?" icons are a symptom: engineers had nowhere structured to put knowledge, so they linked out. Give every block required metadata and the same content renders in the peek panel, the node's config, the assistant's answers and the doc site — authored once.

If it were my call

Ship 1a and 1b together — flattening the library without fixing help just makes 248 undocumented things visible at once, and the peek panel without the flat list still leaves people navigating. Start the 1f metadata contract in the same sprint, because 1b is only as good as the copy behind it and 1d can't work without it. 1c is the highest-leverage single change for the back-and-forth complaint but wants the compatibility rules to exist first. 1e is where the real comprehension win is, and it's the cheapest of the medium-term three if you harvest recipes from builds that already work.
