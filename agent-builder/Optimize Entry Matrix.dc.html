WHAT ACTUALLY NEEDS DESIGNING

Five screens, not nine flows

The matrix collapses to five distinct states. Every entry point is a different starting row through the same five.

1 Ask scope and target — one screen that asks whichever half the door didn't answer. Doors 1 and 2 ask only target; door 5 asks only scope. No door asks both. Mocked as 1c.
2 Ranked recommendations — same list, filtered by whatever the door already fixed. Door 3 is the only one that opens here. Mocked as 1b.
3 Compare — candidate, evidence, results. Every door ends up here. Mocked as 1a.
4 Decide — four endings. Mocked as 1d.
5 Can't proceed — the blocked state. No inputs to replay, metric not attached, no suite. Not yet mocked.
WHAT THE MATRIX EXPOSED

Three things worth deciding

Door 4 hints a target it can't be sure about Arriving from the cost lens implies cost — but someone opening a step from the latency lens may still want it cheaper. The hint has to be visibly changeable, not silently applied.
Doors 5 and 7 skip scope by guessing it A failing metric or a flaky tool implies "the steps involved." That set can be wrong — it needs to be named on the fact row ("3 steps use this model"), not left as "full agent."
Only doors 6, 7 and 8 arrive with a candidate Everywhere else Compare opens empty and needs its own first move — pick a recommendation, or edit a copy by hand. That empty Compare state is the gap in the current mocks.
