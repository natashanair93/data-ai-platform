8a When several things go wrong at once
You're right that the strip is holding four dimensions in one line. It survives because of two rules: the strip has two independent zones, and the left one shows exactly one verdict — the worst, with a count for the rest. It never grows, never wraps, never runs out of room.
LEFT ZONE — WORDS · ONE VERDICT Functionality, safety and quality all compete here, and only the most severe one speaks. Everything else collapses into a +N counter. Truncates with an ellipsis if the reason is long; the counter never truncates.
RIGHT ZONE — NUMBERS · ALWAYS THERE Cost and latency never "fail", so they never need words — they just colour themselves amber when over budget or >2× baseline. Independent channel, so a cost problem and a quality problem never fight for the same pixels.

Why this holds up
The strip's job was never "show four dimensions" — it's "tell me if I need to look, and where." One verdict answers the first half; +N and the deep links answer the second. Adding a fifth dimension later costs a rung on the ladder, not a redesign.
The four-chip strip in the run card stays the place where all dimensions are shown side by side — that's per-run and has the width for it. The node strip is per-node and deliberately narrower in what it claims.
Still an open data question: quality and safety score the run today, not each node. Until they're attributable, rungs 2 and 3 can only light up on the node the evaluator's evidence points at — which is exactly the "first bad step" attribution we sketched earlier.
7a Badge removed — one status channel per node
Yes, remove it. Your instinct about legibility is right, but there's a structural argument that settles it: "tested" and "stale" are properties of the version, not the node. Painting them on every node renders one fact N times, and the one fact that genuinely varies node-to-node — what happened in this run — was stuck competing for the same 20px circle.
WHERE "STALE" GOES It already has a home — v4's amber stale banner above the composer, plus the version stamp on the run. Both are version-scoped, which is what staleness actually is. Nothing is lost by dropping the per-node dot.
WHERE "TESTED" GOES Into the strip's own existence. A node carrying a run strip has been tested; a node with no strip hasn't. The presence of the element is the state — no glyph to learn.
WHAT IT COSTS The badge was scannable at low zoom where text isn't. The strip's colour band survives zoom-out even when its words don't — so the glance still works, it just stops being a code.
The strip now absorbs the two live states the badge and the spinner chip used to split between them, so queued and running become part of the same channel. Seven states, one place to look, every one labelled in words.

What the trade actually buys
Before: two unlabelled channels (a 3-meaning colour dot, plus a spinner chip that replaced the LLM pill) covering lifecycle and liveness, with no room for run outcome, cost or a failure reason. After: one labelled channel covering all seven states, with room for the number that matters per state — and it can hold the deep links (WHY, EVIDENCE) that J2 needs, which a badge never could.
The one thing I'd watch: with the badge gone, the top-right corner of the card is free. Resist filling it — that emptiness is what makes the strip the only place to look.

Drawn on v4's actual node chrome: 300px wide, navy top accent, corner badge at top-right, LLM pill and duration in the footer row. Reference ids: 5a · 5b · 5c, then the full state set in 6a.
The blocker: the corner badge slot is already spoken for
v4's node card already has a corner status badge with a documented vocabulary — grey clock = queued, green check = tested, amber dot = stale — and an explicit rule in the source that it is "never a control". Run status wants the same three colors in the same 20px circle to mean something else: green = ran ok this run, amber = eval failed, red = failed.
So this isn't a styling question. It's: does the badge describe the node's lifecycle, or the last run? Those are different time horizons and both are real. Three answers below.

Two things to decide before I build this
1. Does the strip survive a stale overlay? After C2 lets you edit with results on screen, the strip is describing a run of a version that no longer exists. My instinct: keep it but desaturate the whole strip, since "it failed on the version you just changed" is still the most useful thing on the card.
2. Soft state needs an eval per node, which we don't have. Today toxicity and bias score the run, not each node. Either the amber node state waits for per-node evals, or we attribute a run-level eval failure to the first node whose output the evaluator flagged — which is a data question, not a design one.
